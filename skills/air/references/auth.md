# Auth

Load this for JWT, JWKS, 401, or header questions.

## Partner JWT (AIR APIs)

Header: `x-partner-auth`. Signed **on the server** with `jose` (`RS256` or `ES256`).

| Part | Value |
|---|---|
| Claims | always `partnerId`; issuance needs `scope: "issue"` |
| Header | `kid` matching JWKS `keys[].kid`, `typ: "JWT"` |
| Algorithm | same as the JWKS key (`ES256` if generated by this skill) |
| Expiry | 5 minutes recommended; refuse > 15 minutes |

`kid` convention in this skill: **Partner ID**. Backend `PARTNER_PRIVATE_KEY_KID`, web JWT route, and JWKS `kid` must be the same string. One JWKS URL is registered in the Dashboard; both apps sign against it.

Private key body: PKCS#8 / SPKI base64 **without** PEM headers in env. Code wraps headers on import.

BYO login JWTs also include `email` and `partnerUserId`.

## JWKS

`GET` a JSON document `{ keys: [{ kid, use: "sig", alg, ... }] }` on **public HTTPS**. Register that exact URL in Dashboard → Account → General → JWKS URL.

Localhost and `http://` fail. Login can work while issue/verify 401.

Stub: `skills/air/assets/next-jwks-route.ts`. Check: `node scripts/jwks.mjs --check <url>`.

## Issuer backend keys

| Header | Env | Routes |
|---|---|---|
| `x-api-key` | `API_KEY` | `POST /available-vc`, `POST /issue-vc` |
| `x-admin-api-key` | `ADMIN_API_KEY` | `/admin/*` |
| none | — | `/ready`, `/credential-status/:nonce`, `/.well-known/issuer-did` |

Do not send `x-partner-auth` to those issuer routes. Do not send `x-api-key` to `api.sandbox.mocachain.org` or `air.api.sandbox.air3.com`.

## 401 checklist

1. JWKS URL registered and equal to the live path
2. URL is public HTTPS
3. JWT `kid` === JWKS `keys[].kid`
4. `alg` matches
5. Token not expired — fetch a fresh one per `issueCredential` call
